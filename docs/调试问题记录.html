问题一：Codex CLI 沙箱模式禁止网络操作

记录时间：2026-08-01

问题描述

使用 Codex CLI 执行 git push 等需要网络访问的操作时，命令被拒绝执行。

错误信息

error: cannot run git push: network access is disabled in sandbox mode

原因分析

Codex CLI 默认使用沙箱模式运行命令，出于安全考虑，沙箱会限制网络访问、文件系统写入等敏感操作。

解决方案

修改 Codex 配置文件 C:\Users\htt\.codex\config.toml，添加沙箱例外规则：

[sandbox]
# 允许网络操作的命令白名单
allowed_commands = [
    "git",
    "npm",
    "pip",
    "curl"
]

# 或者使用宽松模式（不推荐用于生产环境）
# mode = "danger-full-access"

也可以在命令行中使用参数临时禁用沙箱：

codex exec --sandbox danger-full-access "git push -u origin main"

验证结果

✓ 配置修改后，Codex 可以正常执行 git push 等网络操作。

问题二：GitHub HTTPS (443端口) 无法连接

记录时间：2026-08-01

问题描述

执行 git push 时无法连接到 github.com，推送超时失败。

诊断过程

步骤 1：检查 Git 代理配置

git config --global --get http.proxy
git config --global --get https.proxy

结果：未配置任何代理。

步骤 2：测试网络连通性

Test-NetConnection github.com -Port 443
ComputerNameTcpTestSucceeded
github.comFalse

结论：HTTPS 端口 443 不通。

步骤 3：测试 SSH 端口

Test-NetConnection github.com -Port 22
ComputerNameTcpTestSucceeded
github.comTrue

结论：SSH 端口 22 可用！

解决方案

方案 A：切换单个仓库远端地址为 SSH

git remote set-url origin git@github.com:cathyhoutt/test-project.git

方案 B：配置全局规则（推荐）

在 C:\Users\htt\.gitconfig 中添加：

[url "git@github.com:"]
    insteadOf = https://github.com/

效果：所有 https://github.com/ 地址自动转换为 git@github.com: SSH 方式。

SSH 密钥配置

确认 ~/.ssh/config 中已配置 GitHub 专用密钥：

Host github.com
    HostName github.com
    User git
    IdentityFile C:/Users/htt/.ssh/id_ed25519_github
    IdentitiesOnly yes
    ForwardAgent yes

验证结果

$ git push -u origin main
branch 'main' set up to track 'origin/main'.
To github.com:cathyhoutt/test-project.git
 * [new branch]      main -> main

✓ 推送成功，后续所有 GitHub 操作自动使用 SSH 通道。

问题三：Codex exec 模式沙箱参数不生效（Windows）

记录时间：2026-08-01

问题描述

在 Windows 上使用 codex exec 执行 git 推送操作时，即使通过 -s workspace-write 参数或配置文件指定沙箱模式，实际运行时仍显示 sandbox: read-only，导致写操作被拒绝。

错误信息

exec "git add README.md; git commit -m '更新安全配置记录'; git push origin main"
 declined in 0ms: rejected: blocked by policy

诊断过程

尝试 1：命令行参数 -s workspace-write

codex exec -s workspace-write "git push origin main"

结果：输出仍显示 sandbox: read-only，参数未生效。

尝试 2：配置文件 ~/.codex/config.toml

sandbox_mode = "workspace-write"

[sandbox]
network_access = true

结果：配置已正确写入，但 exec 模式仍强制使用 read-only。

尝试 3：-c 参数覆盖配置

codex exec -c sandbox_mode="workspace-write" "git push"

结果：仍然无效。

原因分析

Codex 在 Windows 上的 exec（非交互）模式下，由于缺少 Linux 的命名空间隔离机制，会强制降级为 read-only 沙箱以确保安全。命令行参数和配置文件中的沙箱设置在此场景下不生效。

解决方案

方案 A：使用 --dangerously-bypass-approvals-and-sandbox 参数（临时）

codex exec --dangerously-bypass-approvals-and-sandbox "git add README.md && git commit -m '提交信息' && git push origin main"

⚠️ 警告：此参数完全绕过沙箱保护，仅在可信环境下临时使用。

方案 B：使用交互模式（推荐）

codex

在交互模式下，可手动审批每个操作，兼顾安全与可用性。

方案 C：直接使用 git 命令

对于简单的 git 操作，直接在终端执行更可靠：

git add README.md
git commit -m "提交信息"
git push origin main

验证结果

$ codex exec --dangerously-bypass-approvals-and-sandbox "git add README.md; git commit -m '更新安全配置记录'; git push origin main"

sandbox: danger-full-access
...
[main fe4fa11] 更新安全配置记录
 1 file changed, 62 insertions(+), 1 deletion(-)
To github.com:cathyhoutt/test-project.git
   934631b..fe4fa11  main -> main

✓ 使用 bypass 参数后推送成功。
